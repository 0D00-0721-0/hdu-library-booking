# HDU 图书馆即时预约

这个目录是一个独立的小工具。它使用浏览器保存下来的 cookie 登录态，按指定计划提交一次预约请求；默认等到 20:00 再提交。

## 运行

```bash

python instant_book.py --days 2
```

默认会读取 `config.yaml`，预约 `booking.plan` 里的座位，并按 `booking.execute_at` 定时提交。

临时改座位或时间可以直接传参数：

```bash
python instant_book.py --plan 1:1559:130:14:1 --days 0
```

含义是：自习室、六楼杭韵数阁、130 座、今天 14:00 开始、预约 1 小时。

只测试并立即返回、不提交：

```bash
python instant_book.py --dry-run --days 2 --execute-at ""
```

查看当前座位预约：

```bash
python instant_book.py --list-bookings
```

查看当前待签到预约和自动签到时间：

```bash
python instant_book.py --list-checkins
```

自动在预约开始 5 分钟后签到：

```bash
python instant_book.py --auto-check-in
```

指定某条预约自动签到：

```bash
python instant_book.py --auto-check-in BOOKING_ID
```

取消指定预约：

```bash
python instant_book.py --cancel-booking BOOKING_ID
```

定时提交一次：

```bash
python instant_book.py --plan 1:1559:130:8:1 --days 1 --execute-at 20:00:00.500
```

这会先查询并定位座位，然后等到今天的 `20:00:00.500` 再提交，即 20:00:00 后 500ms。刚错过执行点 5 秒以内会立即提交；超过 5 秒会明确停止，避免静默等到次日后提交一个错误日期。

可选的提前预留会在正式提交前指定分钟数，对**主座位**发送一次官方 `lockSeats` 请求；预留成功后仍要在 `execute_at` 调用 `bookSeats` 才算正式预约。页面里的“提前预留主座位”填写 `10`，表示例如 19:50 尝试临时锁座、20:00 按原计划提交；`0` 表示关闭。预留失败或结果不明时不重复锁座，到点仍走原有主座位和备选座位流程。预留可能成功而正式预约仍被“超出可预约座位时间范围”拒绝，所以必须以最终预约列表复核为准。单次预留的官方确认窗口约 15 分钟，不会持续续锁。

命令行可以使用 `--hold-before-minutes 10`。日期偏移按任务启动当天计算，例如周日预约周二须使用 `--days 2`。

如果首包到达时接口还没开放，工具会对“超出可预约座位时间范围”做短窗口有界重试。重试次数和间隔可在网页或 `config.yaml` 的 `max_trials`、`retry_delay` 调整。连接建立超时、429 等确定未提交的临时错误也会有限重试。读超时、连接中断、5xx、提交响应无法解析，或 JSON 可以解析但缺少关键字段时，请求可能已经生效：程序会先复核预约列表，已确认则按成功处理；无法确认则停止重试和换座，并显示“结果待确认”，请刷新当前预约或使用 `--list-bookings` 查询。只有明确的失败响应才进入相应的失败、重试或换座分支。

预约提交遵守至少 **3 秒**的间隔：从上次响应返回（或请求异常结束）开始计时，再允许下一次预约 POST。`retry_delay` 默认和最小值均为 `3`，配置、命令行或网页填入更小值都会按 `3` 处理；更长的自定义间隔继续生效。除了流程中的等待，实际 `book()` 调用也有同账号冷却保护，同一 Python 进程内的重试、换座及连续任务共用该保护。dry-run 和只读查询不占用预约提交次数。此保护不限制其他独立进程或官方客户端的操作。

定时等待提交期间会自动启用 keepalive 心跳，按 `config.yaml` 里的 `request.keepalive_interval` 刷新 Cookie 并校验登录用户；执行前 35 秒不再运行普通心跳，T-5 秒用短超时座位查询做一次预热。剩余不足 3 秒时跳过可选预热；准备或等待结束时如果已错过执行点超过 5 秒，会停止提交。设为 `0` 可以关闭周期心跳。等待期间点击“停止任务”通常会在 0.25 秒内响应，正在进行的网络请求需要先返回。

预热时无法定位的座位会单独移出本次候选列表，其余候选保留原顺序；主座位失效时，使用首个有效备选。所有候选都无法定位，或发现登录失效、验证码要求、无法解析的座位图时停止提交；临时网络错误仍可使用先前准备好的请求。预热更新座位后会同步重建请求参数与签名模板。

定时等待会持续按当前系统时钟核对目标时刻，系统时钟向前或向后校准时会随之调整等待。实际预约请求在冷却结束后再次检查发送时间，避免使用校时前的旧倒计时提前提交；3 秒冷却和心跳间隔仍使用单调时钟。第一次提交错过执行点超过 5 秒，或任意一次提交时预约开始时间已经过去，都会停止。

主座位及备选的固定请求字段、签名固定部分会提前准备；预热改变座位 ID 或提交模式时会重新准备。实际发送前才更新 `api_time` 和签名，Cookie 仍从当前 Session 读取。到点通知和提交日志会在请求结束后写出，避免发包前同步写磁盘；日志中的“发包时间”记录调用预约请求的时刻，不是日志写入时刻，也不是网卡抓包时间。等待期间页面约每 2 秒获取日志，临近执行点时会将下一次轮询延后到执行点之后，提交阶段约每秒刷新。

预约成功响应必须包含 `CODE=ok`、`DATA.result=success` 和 `bookingId`，并通过预约列表复核。复核会校验座位、开始时间、时长及有效状态；超时或“已有预约”没有返回 bookingId 时，还必须匹配唯一座位、楼层或区域名称，避免将不同楼层的同号座位认作成功。网页任务日志会保存到本目录 `logs/`，包括毫秒级发包时间、响应耗时、重试原因和最终复核结果。

取消预约必须复核为“已取消”，续座必须复核为“使用中”；响应丢失或格式不完整时也会查询实际状态，不会自动重发操作。明确拒绝显示失败；查询后仍无法确认、记录消失或预约列表结构无法识别时显示待确认，不会把未知结构当成空列表或操作成功。

自动签到必须收到明确成功响应并复核为“使用中”；如果响应丢失，但查询确认已签到，也按成功处理。复核最多查询 3 次，间隔 0.2 秒。未能确认时显示“待确认”，不会把“仍待签到”“已取消”或记录消失显示成签到成功。命令行结果待确认时退出码为 `2`，普通失败为 `1`。

“停止任务”用于停止等待和后续提交；已经发出的预约或签到请求仍会完成结果复核，成功就显示成功，无法查清就显示待确认。停止任务不会自动取消已经成功的预约，取消预约仍使用单独的操作。

## 本地验证

```bash
python -m unittest -v test_booking_reliability test_local_optimization test_submission_speed test_followup_fixes
python -m unittest -v test_clock_offset test_privacy
node test_web_polling.js
```

新增回归测试使用模拟响应与虚拟时钟，覆盖超时复核、跨楼层同号座位、停止任务、签到状态、预热预算及配置写入失败，也验证响应后 3 秒冷却、连续客户端共享冷却、签名和 Cookie 刷新、慢日志对首包的影响，不会向图书馆发送测试请求。网页保存配置会先校验内容，再原子替换文件，避免写入中断破坏原配置。

复审回归还覆盖预热候选消失、合法 JSON 缺字段、取消和续座复核，以及等待期间的系统校时。页面测试用 Node.js 执行实际页面函数，模拟断连、重连、查询超时、旧请求晚返回和任务丢失；Node.js 仅用于运行页面测试，日常启动工具不需要。

## 网页控制台

Finder 中双击 `start_web.command` 可以直接启动网页控制台。

```bash
cd /path/to/libcs
python web_app.py
```

启动后打开终端里显示的本地地址，例如 `http://127.0.0.1:8765`。网页会读取同一个 `config.yaml`，可以修改预约参数、保存计划、执行 dry-run、立即提交或定时提交，并在页面里实时刷新日志；也可以刷新当前预约列表、取消可取消的座位预约，或对待签到预约开启自动签到。

点击“测量并推荐时间”会进行最多 4 次只读座位图查询，结合每次请求发出、响应到达的本机时间和接口返回的 `nowTime`，估计服务端与本机的时差，并给出预约执行时间建议。按钮在定时任务等待期间也可使用，但距离发包不足 20 秒时会暂停测量，以免影响提交。目前接口返回整秒，单次查询无法得到可信的毫秒级差值；多次采样跨越整秒边界时范围会缩小。如果估计范围跨过零，页面会说明无法判断谁快。已知预约按服务器时间 `20:00:00` 开放，因此建议时间使用范围中“本机可能超前最多”的一端，只向上取整到毫秒，不再额外等待。请求到达服务器会比本机发包更晚，但无法可靠测出单程延迟的下限，因此也不据此提前发包。这要求座位图和预约接口使用同一时钟，且测量后时钟没有明显变化。测量不会自动更改已启动任务的执行时间，也不会发送预约请求。预约任务日志仍会记录单次查询的时差范围，并在提交前预热时更新一次。

页面读取任务状态失败时会保留任务标识，显示“连接恢复中”，以 1、2、4、8 秒逐步延长重连间隔，最长每 10 秒重试一次；每次状态读取最多等待 5 秒。重连只发送状态查询，不重发预约、取消或续座请求。连接恢复后继续显示后台真实状态；若服务重启导致原任务不存在，则显示“待确认”并刷新预约列表。

### 手机访问（Cloudflare Tunnel）

Finder 中双击 `start_cloudflare.command`。脚本会同时启动本地网页服务和 Cloudflare Tunnel，并在终端显示：

- 一个 `https://...trycloudflare.com` 手机访问地址；
- 登录用户名 `hdu`；
- 首次启动时随机生成的登录密码。

密码保存在当前目录的 `.cloudflare-access-password`（权限为仅当前用户可读），后续启动会继续使用同一个密码。不要把这个文件、公开地址或 `config.yaml` 分享给其他人。

临时 Tunnel 运行期间 Mac 必须保持开机、终端窗口必须保持打开；按 `Ctrl+C` 会同时停止 Tunnel 和本地网页服务。Cloudflare 官方将 Quick Tunnel 定位为开发/测试方案，重启后网址会变化。若要固定域名，需要先把一个域名接入当前 Cloudflare 账户，再创建命名 Tunnel 和 DNS 路由。

在网页中从“楼层 / 区域”下拉菜单选择名称即可，页面会自动使用对应的楼层 ID；若配置文件中的旧 ID 不在列表中，需重新选择楼层。设置好预约日期、座位号、开始时间和时长后，点击“立即预约”会忽略“执行时间”输入框并马上提交；它不会清空或改写已保存的定时时间。点击“定时预约”则必须填写执行时间，并等到该时刻再提交。两种模式都会执行登录校验、严格结果判断和预约列表复核。

“座位位置图”会读取图书馆的平面底图与座位坐标。选择楼层和预约时段后，可在图上点击座位填入主座位；切换到“添加备选”后，点击座位可加入或移除备选，最多 5 个。地图可滚动、缩放，刷新按钮会重新查询当前时段的座位状态。图例按官方页面文案区分可用、已占用、锁定（接口状态 2/4）和关闭（状态 3）。官方页面有 15 分钟预留确认流程，但锁定状态本身不保证 15 分钟后释放。若目标时段尚未开放，页面仍会尝试显示平面位置，但不把其他时段的占用状态误标成当前状态。座位状态会变化，最终以提交时接口结果为准。

“备选座位”可以填写一个或多个座位号，例如 `22,23,24`。程序始终先预约主座位；接口明确返回该座位已被占用、锁定、不可用或本次入口尚未开放时，会等待 `retry_delay` 秒后按填写顺序切换。登录失效、验证码、日期或时长错误不会盲目换座。最多可配置 5 个备选座位，留空表示关闭自动换座。

命令行也可以指定备选座位：

```bash
python instant_book.py --days 2 --fallback-seats 22,23 --execute-at 20:00:00.500
```

当前预约列表里选中一条“待签到”预约后，可以点击“签到测试”发送一次受限的 `checkIn` 接口测试。工具会先确认该 `bookingId` 属于当前登录态，并把预检信息、接口响应和测试后的状态写入日志区。

当前预约列表里选中一条“待签到”预约后，也可以点击“自动签到”。工具会获取该待签到任务，计算 `预约开始时间 + 5 分钟` 作为签到时间；例如预约时段是 08:00-20:00，则会在 08:05 发送一次 `checkIn` 请求。等待期间会使用同一套 keepalive 心跳，点击“停止任务”可以取消等待。

预约日期在网页里选择，只作为本次执行参数，不写入 `config.yaml`；可以选择今天、明天或后天。执行时间支持毫秒并会保存到 `booking.execute_at`，例如 `20:00:00.500`；清空表示立即提交。命令行模式需要指定日期时继续使用 `--days`。

如果接口返回“超出可预约座位时间范围”，通常是预约入口还没开放，尤其是预约明天/后天座位时。本工具对应的是 `execute_at`、`max_trials`、`retry_delay`。

## plan 格式

`roomType:floorId:seatNum:startHour:durationHours`

- `roomType`：接口返回的房间类型顺序，通常 `1` 是自习室。
- `floorId`：楼层/区域 id，例如六楼杭韵数阁是 `1559`。
    杭韵数阁（六楼） = 1559
    宋韵云图（四楼） = 1558
    格物E堂（二楼东） = 1557
    数智渊阁（二楼 信息检索室） = 1554
    芯灵驿站（十二楼） = 1543
    比特庭园（二楼西） = 1524
- `seatNum`：座位号，例如 `130`。
- `startHour`：开始小时，例如 `8` 表示 08:00。
- `durationHours`：预约时长，单位小时。

这个工具只在配置的小窗口内做有限重试，不会持续高频请求。

## 隐私与登录态

不要分享 `config.yaml`、Cookie 导出文件、`.cloudflare-access-password` 或运行日志。Cookie 文件建议放在已被 Git 忽略的 `cookies/` 目录中；常见 Cookie JSON、浏览器登录态 JSON 和 `.env` 文件也已加入忽略规则。

HTTPS 请求默认校验证书，建议在配置中保留 `session.verify: true`。已有配置若显式设置了 `verify: false`，应改为 `true`；证书错误应通过修复证书或网络配置解决。

任务日志省略用户姓名和 UID，对请求及响应中的账号、Cookie、令牌等字段进行脱敏，真实请求仍使用原始数据。网页默认配置路径显示为 `config.yaml`，任务日志路径显示为 `logs/` 下的相对路径。日志仍包含预约座位、时段和预约编号，分享前请自行检查。
